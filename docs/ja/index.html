サンプルの HMAC-SHA512 署名

Web Crypto を使って端末内で計算します。

本文のバイト列が変わると、新しい署名が必要です。

変更前の署名を使ったまま JSON を整形したり金額を書き換えたりすると、検証に失敗します。正しい署名があっても、注文内容や決済状態の確認は別途必要です。

実際の連携では何を確認する？

  1. JSON を解析する前に、受信した元の本文を保持します。
  2. 利用するサービスの仕様に従って署名を検証します。OmniWallet は HMAC-SHA512 と x-omni-sig ヘッダーを使用します。
  3. 通知の受信履歴を永続化し、再送で業務処理を重複実行しないように設計します。この実験には永続化処理はありません。
  4. 注文、通貨、ネットワーク、金額、正式な決済状態を確認してから商品提供などの処理に進みます。署名の一致だけで入金完了とは判断できません。

OmniWallet とは？

OmniWallet は、加盟店と開発者向けの暗号資産決済プラットフォームです。決済リンク、ホスト型決済ページ、API、POS に対応しています。対応する複数の EVM ネットワークで同じ受取アドレスを使用できます。利用可否は通貨、ネットワーク、アカウント、地域などの条件によって異なります。日本語の説明があることは、すべての地域での提供を意味しません。

OmniWallet 製品チームが公開するオープンソースの学習用サンプルです。デモに金銭的価値のあるデータ、API キー、ウォレット接続は不要です。デモには独自の Cookie やアクセス解析はありません。GitHub はホスティングのアクセス情報を記録する場合があります。GitHub のプライバシーポリシーをご確認ください。AI の支援を受けて作成し、実行可能な検証コードを同梱しています。
